# 評価ロジック・CPU の大規模監査（2026/11/17）

ゴールデンテスト（`tools/golden`）は「前と同じ結果か」を見る。こちらは「判定と CPU の打ち方が**正しいか**」を
大量のハンドで測る。評価ロジックや CPU を変えたら、修正前（`git archive` で取り出した static/poker）と並べて回す。

## 判定の正しさ: spots.js → analyze.js

```
# 1プロセス分。<seed> を変えて並列に回す（8コアで 8 本）
node tools/audit/spots.js static/poker <seed> <ハンド数> out/s<seed>.jsonl [サンプル率=0.35] [ロールアウト数=16]
FOCUS=1 node tools/audit/spots.js ...   # ポストフロップと「BB でオープンに対応」だけを測る（速い）
node tools/audit/analyze.js out/
```

- あなた役（簡易ルール + 25% ランダム）でハンドを進め、手番の一部を切り出す
- 選べる各アクションについて、アプリの判定（◎◯△×）と、その局面から最後まで打ち切った収支の平均（ロールアウト）を記録する。
  CPU は本物のロジック・本物の手札のまま、残りのボードだけ毎回シャッフル。アクション間で同じ乱数を使う（共通乱数法）
- 1局面の中では CPU の手札が固定なので「その局面の最善手」は透視になる。比べるのは**同じ判定を受けた局面の平均**で、
  判定は見えている情報だけで決まるので偏らない
- analyze.js の主な指標: 「判定が上のアクションの EV − 下のアクションの EV」の平均（正なら判定が正しい方向）。
  比較用に、生の勝率と必要勝率だけで決める素朴な判定（raw）と、CPU の手札を知っている上限（oracle）も出す

## CPU の打ち方: cpu_stats.js → cpu_print.js

```
node tools/audit/cpu_stats.js static/poker <seed> <ハンド数> out/c<seed>.json
node tools/audit/cpu_print.js out/*.json
```

ポジション・ストリート・IP/OOP・ベットサイズ別に、CPU のフォールド/コール/レイズ、Cベット、ドンク、チェックレイズ、
3ベットへの対応、ベットの中身（バリュー/ブラフの割合）、ショーダウン率を出す。
目安は理論値（MDF = ベット前のポット ÷ ベット後のポット。ブラフの割合 = ベット ÷ (ポット + 2×ベット)）と、
公開されている 6max 100bb の解析・実戦統計。

所要時間の目安（M系 Mac 8コア）: spots.js 8本 × 900ハンド（FOCUS=1, ロールアウト12）で約1時間 / cpu_stats.js 8本 × 1000ハンドで約10分。
